対象: `docs/chain-draft.md`、`specification/`、`docs/spec/`、`backend/`、`web/`（Android native を含む）、未コミットの BootReceiver。
締切までの残り時間は把握していない。以下は「デモまで 1〜2 日」を前提にしている。

## 0. 要約

- backend は仕様（S0〜S9、P1 の 1〜10）をほぼ全部実装済み。web も Figma v2 の画面と、Figma に無い画面（通知、ブロック、同意、グループの投票・招待・グラフなど）まで揃っている。量は十分で、足りないのは **デモの主動線が実機でつながっていないこと** と、**コンセプトの核である「ちかく」画面が無いこと**の 2 点。
- **重大なバグが 2 件ある。** (B1) クライアントが `POST /party/presence` を一度も呼ばないので、実機では Party が始まらない。(B2) すれ違いの常駐処理が画面ごとにマウントされているので、画面を移るたびに BLE が止まって再起動し、投稿画面などでは止まったままになる。
- 残り時間は新機能を足さずに、**「すれ違い → 友達 → 再会で Party → 写真 → memory」の通しを 2〜3 台の実機で動かすこと**と、**「ちかく」を Figma の Nearby（泡のグラフ）にすること**だけに使う。他の機能は凍結する（消さずに、導線から外す）。

## 3. 方向性と、残り時間でやること

### 3.1 方針

1. **デモの筋書きを 1 本に決め、それが通ることを最優先にする。** 筋書き案: 「A と B がすれ違う → 互いが見える → 友達になる → 再会すると 30 秒で仮 Party、5 分で本 Party → 写真を共有 → 離れると終わって memory に残る」。並行して「近くのグループに入って投稿する」を見せる。
2. **新しい機能は足さない。** 足すのは、筋書きをつなぐ部品と「ちかく」画面だけにする。
3. **作り込んだ周辺機能は凍結する。** 消さずに、導線（タブやヘッダーのアイコン）から外すか、そのまま放置する。§4.2 に一覧を置く。

### 3.3 Party の近接報告（作業 3）の仕様

- 置き場所: `web/src/device/proximity/` に `party.ts`（純粋な関数）と、パイプラインへの組み込み。native は変更しない
- `GET /party/friend-beacons` を、パイプラインの開始時、3 時間ごと、WebSocket の `friend.changed` を受けたときに取る。`token → did` の表を作る
- native の `sighting` イベント（同じ token は 5 秒に 1 回届く）を表で引き、friend なら `lastSeen[did] = { seenAt, rssi }` を更新する
- 15 秒ごとに、45 秒以内に見えた friend がいれば `POST /party/presence { observations: [{ did, lastSeenAt, rssi }] }` を送る。全員いなくなったら空の配列を 1 回送る
- 確かめること: `sighting.token` と friend-beacons の `token` の表現（base64url、padding の有無）が一致するか
- 制約: `sighting` イベントは WebView が動いている間しか届かない。デモはアプリを前面に出して行うので問題ないが、バックグラウンドでの Party 成立は後回しにする
- 代わりの最短手: backend の `EncounterService.Sightings` で、相手が friend なら `ObservePeerEdge` も呼び、JS の sighting 送信間隔を 15 秒にする。backend 1 か所の変更で済むが、sightings のレート制限と送信量が増えるので、上の案を推す

### 3.4 「ちかく」画面（作業 6）の仕様

`BubbleCanvas` を使う。BLE の token は、公開時刻までは相手を伏せる設計なので、知らない人は匿名で数だけ出す。

| 泡 | データ | 表示 |
| --- | --- | --- |
| 中心 | 自分。Party 中なら Party（`/party/current`） | 自分のアバター、または Party の波形 |
| 近くの友達 | 3.3 の `lastSeen`（45 秒以内） | アバター。タップでプロフィール |
| 近くの知らない人 | `useNearbyTokens()` のうち friend でない token | 名前なしの小さな泡。「近くに n 人」 |
| グループ | `/groups/nearby` の inside / near | `memberCount` に比例する大きさの円。open と closed で色を分ける（Figma の色） |

- 下に「今日のすれ違い」（`/encounters` の今日分。公開前のものは「？ まだ見えません」）
- 今の一覧（参加・退出ボタン）は、グループの泡をタップしたときのシートに移す

### 4.2 未コミットの差分（BootReceiver / BootState）

- 方向は仕様（android §5）どおりで、コードにも問題はない。`ProximityState.load` は `ProximityService.onCreate` でも呼ぶので重複しているが、害はない
- ただし B2 があるうちは、BootState が「ユーザーが start した」ことを表していない。画面を移るたびに false と true を行き来し、Compose を開いたまま再起動すると再開しない。**B2 を先に直してからコミットする**
- Android 15 で `BOOT_COMPLETED` から `connectedDevice` の FGS を起動できるかは、実機で確かめていない（V5）。`startForeground` の失敗は catch しているので、落ちはしない
- token が切れた状態で再開すると、advertise はせず scan だけ続ける（`tokens_exhausted`）。JS が起動するまで、sighting は Room にたまる。それでよい
